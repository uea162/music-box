# Music Box 验收用例

## 测试环境
qa 会把每个 PR 的分支拉到本地，跑生产构建（`npm run build` 然后 `npm start`），用 Chrome 测三种窗口尺寸：1440×900、768×1024、390×844。手机尺寸开触摸模拟。Safari 暂无真机，相关用例标为“待真机”。

V11 和 M5 只在生产构建上测，不在 `npm run dev` 下量帧率。

PR 描述里引用用例编号即可，例如“覆盖 R1–R6”。

## 基础回归 V（每个 PR 都在桌面尺寸跑一遍）
- V1 页面加载后不做任何操作，各列卡片缓慢上下移动（偶数列向上、奇数列向下），墙体不横移。
- V2 桌面中心卡宽约 239px，外圆角约 25px，封面圆角约 18px。
- V3 中心卡最大、最亮；越往两侧越小、越暗、越偏转、越靠后。
- V4 同屏约三行卡，没有大片半透明重影。
- V5 四周有暗角，而且不挡鼠标操作。
- V6 标题、右上计数和底部面板固定不动。
- V7 鼠标移到四角时墙体有轻微视差，UI 不动。
- V8 拖拽时墙体跟手，松手后不回弹；快速甩动后会滑行一小段再停下。
- V9 滚轮纵向浏览，触控板横向手势能移动墙体。
- V10 点卡片会出现白色圆角框并开始试听，再点一次暂停。
- V11 播放时进度条正常更新，60Hz 屏幕上帧率不低于 55fps。
- V12 控制台没有报错。

## P0.4 断点重排 R
- R1 不刷新页面，把窗口从桌面宽度拖到手机宽度（跨过 1180 和 720）后，布局和在该尺寸下直接打开页面一致。
- R2 反方向（手机拖到桌面）同样一致。
- R3 任何缩放（同档内或跨档）都不重建场景：画面不闪，Network 面板里没有重新请求封面。墙体按新宽度连续缩放，只有列需要补更多槽时才重新分配卡片。
- R4 播放中跨断点缩放，音乐不断，选中框仍在同一首歌上。
- R5 在 `npm run dev` 下测：先确认刚打开页面时 `window.__musicBoxDebug.activeLoops()` 返回 1，记下 `window.__musicBoxDebug.memory()` 返回的初始几何体和贴图数量；然后来回跨断点 10 次，确认计数回到初始值、`activeLoops()` 仍是 1。Chrome 内存快照作为补充，看 JS 堆内存有没有持续上涨。（调试挂钩 `window.__musicBoxDebug` 仅开发模式存在。）
- R6 快速连续拖动窗口大小，不报错，也不卡死。

## P0.1 聚焦 F
- F1 点 “Pick one record” 后，选中卡完整显示在屏幕内，不过度放大。
- F2 聚焦和结果面板显示期间各列停止移动。返回后如果试听还在播放，墙体继续保持静止（播放时目标速度为 0）；暂停或播完后平滑恢复，不跳动。
- F3 结果面板里的歌和聚焦的卡一致，播放的也是这首歌。
- F4 返回后卡片缩放复原，选中状态正确。
- F5 连续快速点击，或在动画进行中点击，不会卡在中间状态。
- F6 平板和手机尺寸同样通过 F1–F5。
- F7 窗口宽 821、1000、1189 时点 “Pick one record”：结果面板整块都在屏幕内，“Back to the wall” 完整可见并且点得到（821 宽时它以前完全在屏幕外）。
- F8 结果面板打开时把窗口拖过 820（例如 1440 → 700 → 1440）：聚焦卡重新回到屏幕中心，缩放换成新宽度对应的值（820 以下 1.1，以上 1.38），面板仍在屏幕内。

## 球面墙 S（对照 `docs/REFERENCE-LAYOUT.md`）
- S1 开启“减少动态效果”后打开页面，用 `docs/reference-layout/layout_sim.py --mode ours --songs <曲目数> --reduced-motion` 在同一视口下对照：1440×900 中心卡（第 7 列第 3 槽）投影 x 范围约 601–839，其他可见卡片轮廓偏差 ≤ 3 px，可见列集合和并排半宽卡位置一致。768×1024、390×844 同样对照。
- S2 墙面是球面：越往左右上下，卡片越窄越矮、越暗，中心卡最大最亮。并排半宽卡只出现在宽度 ≥ 200 的列，位置是每列第 2、5、8… 槽。
- S3 每列各自移动：偶数列向上、奇数列向下，速度各不相同；墙体不横移。
- S4 开场各列先快后慢，大约 2 秒内慢到正常速度的 2 倍以下，之后保持正常速度。
- S5 在墙上按住不动：所有列（不只按住的那一列）约 300 ms 内停下；松手后慢慢恢复，约 1.5 秒恢复到正常速度的 2/3 以上。
- S6 竖直拖拽时所有列一起移动相同距离，卡片跟手（屏幕中心附近指针移动 5 px，卡片约移动 5 px）。水平拖拽时整面墙横移。
- S7 快速甩动后立即松手，墙体继续滑行一小段（参考站点实测 54–94 px）后停下；各列滑行距离相同。
- S8 拖动后停住超过约 0.1 秒再松手，墙体不滑行。
- S9 正在播放、或聚焦（Pick one record）期间各列停止移动；暂停后立即开始恢复。
- S10 播放中来回跨断点 10 次：声音不断，墙上始终只有一张白框且在同一首歌上；如果这张卡被屏幕边缘切掉（哪怕中心还在屏内），停止缩放后它会回到屏幕中心。

## 减少动态效果 S-RM
- S-RM1 系统开启“减少动态效果”后打开页面：各列不自动移动，也没有开场加速。
- S-RM2 拖拽仍然跟手（指针移动多少，墙面移动多少）；快速甩动后松手，墙体立即停住，不滑行。
- S-RM3 页面开着时切换系统设置即时生效，不用刷新：打开“减少动态效果”后各列立即停下；关闭后各列从静止慢慢恢复到正常速度，不会重新出现开场加速。
- S-RM4 视差关闭；点 “Pick one record” 时墙体直接跳到聚焦卡，不做滑动动画。
