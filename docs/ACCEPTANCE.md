# Music Box 验收用例

## 测试环境
qa 会把每个 PR 的分支拉到本地，跑生产构建（`npm run build` 然后 `npm start`），用 Chrome 测三种窗口尺寸：1440×900、768×1024、390×844。手机尺寸开触摸模拟。Safari 暂无真机，相关用例标为“待真机”。

V11 和 M5 只在生产构建上测，不在 `npm run dev` 下量帧率。

PR 描述里引用用例编号即可，例如“覆盖 R1–R6”。

## 基础回归 V（每个 PR 都在桌面尺寸跑一遍）
- V1 页面加载后不做任何操作，卡片墙缓慢持续横移。
- V2 桌面中心卡宽约 220–230px，外圆角约 25px，封面圆角约 18px。
- V3 中心卡最大、最亮；越往两侧越小、越暗、越偏转、越靠后。
- V4 同屏约三行卡，没有大片半透明重影。
- V5 四周有暗角，而且不挡鼠标操作。
- V6 标题、右上计数和底部面板固定不动。
- V7 鼠标移到四角时墙体有轻微视差，UI 不动。
- V8 拖拽时墙体平滑跟随，松手后不回弹。
- V9 滚轮纵向浏览，触控板横向手势能移动墙体。
- V10 点卡片会出现白色圆角框并开始试听，再点一次暂停。
- V11 播放时进度条正常更新，60Hz 屏幕上帧率不低于 55fps。
- V12 控制台没有报错。

## CI 与文档 C
- C1 提 PR 后自动按顺序跑 `npm ci`、`lint`、`build`、`typecheck`，全部通过。
- C2 `HANDOFF.md` 第 7 节已改成以 GitHub `main` 为准。

## P0.4 断点重排 R
- R1 不刷新页面，把窗口从桌面宽度拖到手机宽度（跨过 1180 和 720）后，布局和在该尺寸下直接打开页面一致。
- R2 反方向（手机拖到桌面）同样一致。
- R3 在同一档宽度内缩放（比如 1400 到 1200）不重建场景：画面不闪，Network 面板里没有重新请求封面。
- R4 播放中跨断点缩放，音乐不断，选中框仍在同一首歌上。
- R5 在 `npm run dev` 下测：先确认刚打开页面时 `window.__musicBoxDebug.activeLoops()` 返回 1，记下 `window.__musicBoxDebug.memory()` 返回的初始几何体和贴图数量；然后来回跨断点 10 次，确认计数回到初始值、`activeLoops()` 仍是 1。Chrome 内存快照作为补充，看 JS 堆内存有没有持续上涨。（调试挂钩 `window.__musicBoxDebug` 将在 P0.4 的 PR 中加入，仅开发模式存在。）
- R6 快速连续拖动窗口大小，不报错，也不卡死。

## P0.1 聚焦 F
- F1 点 “Pick one record” 后，选中卡完整显示在屏幕内，不过度放大。
- F2 聚焦和结果面板显示期间墙体暂停横移，返回后平滑恢复，不跳动。
- F3 结果面板里的歌和聚焦的卡一致，播放的也是这首歌。
- F4 返回后卡片缩放复原，选中状态正确。
- F5 连续快速点击，或在动画进行中点击，不会卡在中间状态。
- F6 平板和手机尺寸同样通过 F1–F5。

## P0.3 循环接缝 L
- L1 本地临时调高速度观察一整圈，接缝处没有空洞、抖动或间距突变。
- L2 用正常速度 `0.105` 在桌面上至少看接缝经过一次（大约 214 秒）。
- L3 向左、向右拖过接缝都连贯。
- L4 纵向滚动越过每列的循环点也没有空洞。
- L5 PR 的改动里没有调试速度或调试开关。

## P0.2 多尺寸回归 M（整体验收）
- M1 三种尺寸下卡片都铺满画面，边缘没有空白。
- M2 圆角和间距清楚。
- M3 底部面板不挡中心主卡。
- M4 手机尺寸下触摸拖拽正常，页面本身不跟着滚动或回弹。
- M5 拖拽和播放时帧率稳定。
- M6 开启“减少动态效果”后，自动横移和视差都关闭，拖拽仍然可用。
